# Core architecture forensic audit

Date: 2026-09-14. Scope: `src/neural_network.py`, every production file in `src/neural_network_module`, `model_management`, and generation/configuration call paths in `model/cevahir.py`. Source references describe the **pre-change** code inspected in this audit. No application code was changed and no tests were run by this audit worker. Runtime reports, if included in the consolidated audit, must be distinguished from these source findings.

`IMPLEMENTED` below means a real implementation is reached by the documented core call path and its basic operation can be verified from source. It does not mean every combination is correct or a performance advantage has been measured. Broken compositions are listed explicitly. Unexecuted hypotheses are labeled as such.

Main path:

1. `Cevahir._init_model` (`model/cevahir.py:1229`) constructs `ModelManager`.
2. `ModelManager.build_model` (`model_management/model_manager.py:225`) calls `ModelInitializer.build_model`.
3. `ModelInitializer` signature-filters flat dictionaries (`model_initializer.py:122`), constructs `CevahirNeuralNetwork` (`:226`), and moves the whole model to its device (`:227`). Optional compile, quantization, and distributed wrapping follow.
4. `CevahirNeuralNetwork` uses `LanguageEmbedding`, `PositionalEncoding`, N `TransformerEncoderLayer`s, final norm, tied/untied vocabulary projection (`src/neural_network.py:324`, `:335`, `:391`, `:460`, `:472`). `seq_proj_dim` is retained as an API/config field, but no sequence projection exists (`:309`).
5. Each layer always instantiates `MultiHeadAttention`, irrespective of `attention_type` (`transformer_encoder_layer.py:220`), then dense FFN or sparse MoE (`:260`). Forward selects sequential pre/post norm or parallel residual (`:505`).
6. `ModelAPI.generate` calls autoregressive generation (`model/cevahir.py:523`), which calls `ModelManager.forward` (`:635`). The manager delegates cache flags only if found in `model.forward.__code__.co_varnames` (`model_manager.py:535`), which is fragile for compiled/distributed wrappers.

## Prioritized correctness findings and regression candidates

1. **P0: Cached RoPE and causality are not equivalent to full causal forward.** `MHA:765` never supplies cache_position to RoPE, so every incremental token is position 0. `Sk` is captured from incoming K (`:715`), never updated after cached K expands (`:797`). Default SDPA uses upper-left `is_causal=True` (`:501`) for a 1×N query/key relation, admitting only the earliest key, whereas incremental decoding needs all prior retained keys. Explicit masks/sliding windows also use stale dimensions (`:825`, `:847`, `:868`). Test full vs tokenwise and chunked logits for MHA/MQA/GQA with RoPE, manual/SDPA, and padding/window combinations.
2. **P0: Flash fallback can leak future tokens.** Main attention supplies mask=None to external Flash (`MHA:889`); fp32 or runtime failure falls back to manual attention with that None (`:531`, `:591`), and manual attention has no causal argument. Padding and windows are discarded even if external Flash succeeds. Test a mocked/forced external backend with fp32 and an exception; modify future tokens and assert prefix outputs unchanged.
3. **P0: Auxiliary MoE objective is dropped and graph retention remains.** The only consumer API has no external Python caller. Replacing a list of loss tensors with scalar sums (`Layer:598`) does not remove referenced graphs. Return/combine the current aux objective in the actual training contract, ensure no double alpha, and test router gradient, two optimizer steps, gradient accumulation, checkpointing parity, and reset lifecycle.
4. **P0: Cache eviction is bypassed by generation.** Indexed writes reject positions >= capacity (`KV:229`), whereas the generation loop uses monotonically increasing indexed positions. Append eviction uses overlapping copy (`KV:368`) that may raise a PyTorch overlap error (not executed in this audit) and cannot fit incoming chunks larger than available non-sink capacity. Test overflow, oversized prompt, sinks, variable batch, reset, and positional semantics after eviction. `_seen_tokens` also does not reset on a changed batch (`KV:203`), and increments before writes succeed (`:221`).
5. **P0: Quantization facade reports completion without applying the returned model.** `CevahirNeuralNetwork.apply_quantization` (`src/neural_network.py:919`) ignores `quantize_model` return. Dynamic INT8 (`quantization_manager.py:300`) is out-of-place. The facade then reports the unchanged model. The initializer's bitsandbytes path replaces specialized quantized weight parameters with plain original parameters (`model_initializer.py:626`), requiring real backend verification, not class-name counting. Core rejects int4 before initializer can handle it. Regression tests must check converted module/weight types, finite outputs, reload, and actual serialized bytes; absent hardware should be reported as unavailable.
6. **P0: Typed schema does not represent executable configuration.** Details below. Preserve old defaults and checkpoint weights through explicit migration; do not silently reinterpret legacy flags.
7. **P0: Manager padding masks corrupt left/irregular padding.** `model_manager.py:513` counts valid tokens and enables the first valid_len positions, ignoring actual mask indices. Cached mask dimensions and arbitrary additive 2-D masks are also conflated. Test right, left, internal padding with a sentinel perturbation of masked tokens.
8. **P1: Manual fully masked rows attend uniformly.** `MHA:630` computes -inf minus -inf then `:634` turns NaNs into 0, giving uniform probability over forbidden keys. Match SDPA's zero-output behavior and test all-masked rows plus finite gradients. SDPA and external Flash multiply temperature into scale (`:492`, `:544`), manual attention divides (`:612`); temperature≠1 paths disagree.
9. **P1: Unused trainable parameters risk DDP behavior.** MHA allocates `self.norm` (`MHA:334`) but returns raw projection without it (`:907`). Parallel residual additionally does not use norm2 (`Layer:665`). DDP default `find_unused_parameters=False` (`model_initializer.py:704`) needs a two-step multi-process check; removing unused state requires a compatibility migration, not blind deletion.
10. **P1: Checkpoint compatibility only checks envelope version.** `model_saver.py:285` saves model/optimizer/scheduler/config/epoch and version metadata; it does not centrally save RNG/scaler/global training step. `model_loader.py:316` loads state_dict directly; no old separate gate/up to merged `gate_up_proj` weight migration was found. `load_all` also reconstructs directly. Existing V-number comments cannot be used as a checkpoint ABI.

## Configuration consolidation findings

- There are two incompatible classes named `CevahirConfig`: `model/cevahir.py:365` (app facade, tokenizer/model dictionaries) and `model_management/config_schema.py:429` (nested typed architecture/training/etc.). The typed class is exported in `model_management/__init__.py`, but production construction paths inspected here do not use it.
- `ModelArchConfig` omits `use_pytorch_sdpa`, `use_qk_norm`, `parallel_residual`, both soft-cap fields, drop-path, sink/eviction, advanced checkpointing, and the router's jitter/alpha. Its `from_dict` silently discards unknown keys (`config_schema.py:54`), so converting today's config can drop effective capabilities.
- Default drift: typed `num_layers=8` vs core constructor `12`; typed Flash=true vs core false; typed `effective_ffn_dim=4D` (`config_schema.py:237`) vs core SwiGLU round-up-to-256 of 8D/3 (`src/neural_network.py:355`). Typed quantization accepts none/int8/int4 (`config_schema.py:216`), core accepts none/fp16/bf16/int8_dynamic/int8 (`quantization_manager.py:55`). `seq_proj_dim=None` is an accepted typed default but core's original signature requires a concrete argument and retains obsolete weight-tying checks.
- `ModelInitializer._filter_kwargs_for_ctor` (`:126`) drops all parameters that are only accepted through `**kwargs`. Thus even recognized core `pe_max_len`, `pe_dropout`, `rope_original_max_len` are lost through the manager. Core itself never forwards `kv_eviction_strategy`/`kv_num_sink_tokens` to layers.
- `CevahirConfig.from_dict(CevahirConfig.to_dict())` inherits shallow `_SchemaBase.from_dict`; nested dictionaries are not reconstructed into dataclasses, so subsequent validation raises instead of round-tripping. No schema_version/migration registry exists.
- Validation performs modulo by zero after recording zero head counts (`config_schema.py:185`, `:201`), misses head-dimension-even RoPE constraint, and does not validate every interval/enum. `DistributedConfig.strategy` is not automatically mapped to initializer's `distributed_strategy`; typed quant fields likewise use a different key vocabulary.
- Reuse and evolve `model_management/config_schema.py` as the architectural typed source. Keep app facade as an adapter with explicit legacy conversion. Introduce schema version, explicit capability enums, one canonical normalization to core kwargs, strict new-config validation, lossless known-field migration, and constructor/checkpoint round-trip tests. Preserve current weight layouts while introducing aliases/migrations rather than deleting old fields.

## Benchmark reuse and missing metrics

Reuse `ModelProfiler` instead of introducing a second profiler:

| Existing API | Reusable result | Corrections or missing context |
|---|---|---|
| `count_parameters(model, log=False)` (`profiler.py:185`) | `ParamStats`: total/trainable/frozen/by_layer | Overall parameter iteration deduplicates tied weights; `by_layer` sums can double-count shared weights. `trainable_mb` is explicitly float32 estimate, not current dtype storage. |
| `memory_snapshot(device, log=False)` (`:237`) | allocated/reserved/free/total/device | Add reset/max allocated peak metric and represent absent CUDA as unavailable, not measured 0 VRAM. |

| `estimate_flops(...)` (`:295`) | `FlopEstimate` | It reads `model.config`, absent in the core (`_ctor_cfg` is used), and silently assumes 512D/8L/8H. Formula misses attention ×V matmul, vocab projection, SwiGLU third matrix and sparse active-expert accounting. Fix before scientific comparison. |
| `benchmark_forward(model, sample, n_warmup, n_runs)` (`:360`) | latency mean/std/min/max, tokens/s | Uses perf_counter or CUDA events; leaves model in eval mode. Separate prefill from decode, restore modes/RNG, explicitly sync devices, and reject zero repetitions. |
| `profile_context(...)` (`:433`) | real torch.profiler context | Extend reporting for compile graph breaks/recompilation; do not claim compiled speed from wrapper construction alone. |
| `full_report(...)` (`:488`) | dictionary of dataclass reports | Dataclasses require serialization to JSON; automatic manager call has timing disabled (`model_manager.py:278`). It can sample out-of-vocabulary ids for tiny models because core lacks a vocab_size property (`profiler.py:519`). |

Required additions: active parameters/token, explained FLOPs/token estimate, all-layer allocated/used KV bytes/token, prefill/decode/training throughput, separate forward/backward latency, validation loss/perplexity, gradient norm/NaN/Inf, router utilization/entropy, optional attention entropy (explicit unavailable under fused attention), checkpoint bytes, deterministic seed/config/environment record, baseline/experiment/delta JSON. Use small synthetic data only as a plumbing/stability benchmark; do not present random-model loss as evidence of language quality or faster convergence.

## Test plan and evidence boundary

No runtime test was executed by this worker. The audit is source-based and explicitly identifies conditional/unexecuted backend risks. Existing shape tests are insufficient for cached/full numerical equivalence, absence of future/padded-token leakage, quantization actually changing modules, persisted configuration round trips, and actual MoE objective integration. Those checks precede new architecture work. CUDA-specific Flash/bitsandbytes/distributed claims require separately marked backend tests and cannot be certified by CPU-only execution.
